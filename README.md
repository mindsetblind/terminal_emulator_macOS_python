# terminal_emulator_macOS_python


Учебный проект: эмулятор языка оболочки UNIX-подобной ОС.

## Этап 1 — REPL

Минимальный прототип с графическим интерфейсом. Большинство команд —
заглушки, но диалог с пользователем уже полностью поддерживается:
ввод команды, парсинг, обработка ошибок, вывод результата.

### Возможности

- Графический интерфейс (Tkinter): поле ввода команд, область вывода,
  кнопка "Выполнить"
- Заголовок окна формируется из реальных данных ОС:
  `Эмулятор - [username@hostname]`
- Парсер аргументов с поддержкой кавычек (через `shlex`) —
  корректно разбирает строки вида `cd "My Folder"`
- Команды-заглушки `ls` и `cd` — выводят своё имя и переданные аргументы
- Дополнительные команды: `help` (список доступных команд),
  `clear` (очистка окна вывода), `echo` (вывод переданного текста)
- Команда `exit` — завершает работу эмулятора
- Обработка ошибок: незакрытые кавычки, неизвестная команда, пустой ввод

### Запуск

```bash
./run.sh
```

### Тесты

```bash
python3 -m unittest discover tests
```

### Структура проекта

- `run.sh` — скрипт запуска, передаёт все аргументы в `src/main.py`
- `src/main.py` — точка входа
- `src/cli.py` — параметры командной строки (`parse_args`)
- `src/gui.py` — класс `TerminalApp`, графический интерфейс и выполнение команд
- `src/parser.py` — парсер командной строки (`pars_command`)
- `src/commands.py` — реализация команд и диспетчер `COMMANDS`
- `src/script.py` — чтение стартового скрипта (`load_script`)
- `src/vfs.py` — виртуальная файловая система: загрузка, сохранение, VFS по умолчанию
- `vfs/` — примеры VFS в формате XML
- `scripts/` — стартовые скрипты и демонстрационные `.sh`-скрипты
- `tests/` — unit-тесты (`python3 -m unittest discover tests`)

### Примеры работы

**Обычная команда:**
```
> ls -la
ls: команда вызвана с аргументами -la
```

**Аргумент в кавычках:**
```
> cd "My Folder"
cd: команда вызвана с аргументами My Folder
```

**Без кавычек — аргументы разделяются по пробелу:**
```
> cd My Folder
cd: команда вызвана с аргументами My, Folder
```

**Ошибка — незакрытая кавычка:**
```
> cd "test
Ошибка: незакрытые кавычки
```

**Ошибка — неизвестная команда:**
```
> foobar
Ошибка: команда не найдена
```

**Завершение работы:**
```
> exit
Завершение сессии...
```

## Этап 2 — Конфигурация

Эмулятор настраивается при запуске через параметры командной строки
и умеет выполнять команды из стартового скрипта.

### Параметры командной строки

| Параметр | Описание |
|---|---|
| `--vfs ПУТЬ` | путь к физическому расположению VFS (XML-файл, см. этап 3) |
| `--script ПУТЬ` | путь к стартовому скрипту |
| `-h`, `--help` | справка по параметрам |

```bash
./run.sh --vfs vfs/minimal.xml --script scripts/start.txt
```

При запуске в окне выводятся все заданные параметры:
```
[debug] VFS: vfs/minimal.xml
[debug] Стартовый скрипт: scripts/start.txt
```

### Стартовый скрипт

Текстовый файл с командами эмулятора, по одной на строку:
- строки, начинающиеся с `#`, и пустые строки пропускаются;
- `#` вне кавычек начинает комментарий до конца строки;
- каждая команда выводится в окне как `> команда`, а под ней результат —
  как будто её ввёл пользователь;
- при первой ошибке выполнение скрипта останавливается с указанием
  номера строки;
- команда `exit` завершает скрипт и закрывает окно.

Пример (`scripts/start.txt`):
```
# Стартовый скрипт эмулятора
help
ls -la  # комментарий после команды
cd "My Folder"
foobar
ls после ошибки
```

Результат:
```
> help
Список доступных команд: echo, clear, help, cd, ls, exit, vfs-save
> ls -la  # комментарий после команды
ls: команда вызвана с аргументами -la
> cd "My Folder"
cd: команда вызвана с аргументами My Folder
> foobar
Ошибка: команда не найдена
Скрипт остановлен: ошибка в строке 5
```

Если файл скрипта не найден:
```
Ошибка: не удалось открыть стартовый скрипт scripts/nope.txt
```

### Демонстрационные скрипты

| Скрипт | Что демонстрирует |
|---|---|
| `scripts/demo_no_args.sh` | запуск без параметров |
| `scripts/demo_vfs.sh` | только `--vfs` |
| `scripts/demo_script.sh` | только `--script` |
| `scripts/demo_all.sh` | оба параметра |
| `scripts/demo_error.sh` | скрипт с ошибкой, выполнение прерывается |
| `scripts/demo_exit.sh` | скрипт с командой `exit` |
| `scripts/demo_missing_script.sh` | несуществующий файл скрипта |
| `scripts/demo_help.sh` | справка `--help` в терминале |

Скрипты можно запускать из любой папки, например:
```bash
./scripts/demo_all.sh
```

## Этап 3 — VFS

Эмулятор работает с виртуальной файловой системой (VFS), которая
хранится только в памяти. Файлы на диске не распаковываются и не
изменяются — кроме служебной команды `vfs-save`.

### Формат VFS

Источник VFS — XML-файл. Корневой элемент `<vfs>`, внутри — папки
`<dir name="...">` и файлы `<file name="...">`. Содержимое файлов
хранится в base64, поэтому в VFS можно положить и двоичные данные.

```xml
<?xml version="1.0" encoding="utf-8"?>
<vfs>
  <file name="root.txt">0KPRgNC+0LLQtdC90YwgMQ==</file>
  <dir name="home">
    <dir name="user">
      <file name="todo.txt">0KPRgNC+0LLQtdC90YwgMw==</file>
    </dir>
  </dir>
  <dir name="tmp"/>
</vfs>
```

### Загрузка VFS

- `--vfs ПУТЬ` — VFS загружается из указанного XML-файла.
- Без `--vfs` — в памяти создаётся VFS по умолчанию
  (`/home/user/readme.txt`).
- При ошибке загрузки выводится сообщение, и эмулятор продолжает работу
  с VFS по умолчанию. Обрабатываются ошибки: файл не найден, неверный
  XML, неверная структура (другой корневой элемент, неизвестный элемент,
  нет атрибута `name`, повторяющееся имя, содержимое не в base64).

После загрузки в окне выводится отладочная строка:
```
[debug] Загружена VFS vfs/nested.xml (папок: 6, файлов: 4)
```

Пример ошибки:
```
Ошибка загрузки VFS: неверный формат XML: vfs/broken.xml
[debug] Загружена VFS по умолчанию (папок: 2, файлов: 1)
```

### Команда `vfs-save`

`vfs-save ПУТЬ` сохраняет текущее состояние VFS на диск в том же
формате XML. Сохранённый файл можно снова загрузить через `--vfs`.

```
> vfs-save /tmp/emulator_vfs.xml
VFS сохранена в /tmp/emulator_vfs.xml
> vfs-save /нет/такой/папки/vfs.xml
Ошибка: vfs-save: не удалось записать файл: /нет/такой/папки/vfs.xml
> vfs-save
Ошибка: vfs-save: не указан путь
```

### Примеры VFS

| Файл | Содержимое |
|---|---|
| `vfs/minimal.xml` | минимальная VFS: один файл |
| `vfs/several_files.xml` | несколько файлов, включая двоичный `pixel.png` |
| `vfs/nested.xml` | папки и файлы с вложенностью до 5 уровней |
| `vfs/broken.xml` | ошибка: неверный XML |
| `vfs/wrong_format.xml` | ошибка: неверный корневой элемент |

### Стартовый скрипт этапа 3

`scripts/stage3.txt` проверяет все команды этого и прошлых этапов:
`help`, `echo` с комментарием, `ls`, `cd`, сохранение VFS через
`vfs-save` и ошибку записи, на которой скрипт останавливается.

| Скрипт | Что демонстрирует |
|---|---|
| `scripts/demo_vfs.sh` | минимальная VFS |
| `scripts/demo_vfs_several.sh` | VFS из нескольких файлов |
